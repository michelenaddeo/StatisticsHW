Toy ECC encryption, the Caesar cipher and their attacks

One message is encrypted with a toy scheme on secp256k1 and with a Caesar cipher. Both are then attacked: the Caesar cipher with letter statistics, the toy ECC scheme through its restricted private-key space.

Message

The same plaintext is used by both schemes.

1Toy ECC encryption on secp256k1

A hybrid, ElGamal-style scheme (the idea behind ECIES) on the real secp256k1 curve with the generator G of the previous homework. The private key d is restricted to bits so that experiments stay feasible.

  • Keys. Private key d ∈ [1, 2b); public key Q = dG. Q is published, d is secret.
  • Encryption. Choose a fresh random r and send R = rG. Compute the shared point S = rQ, derive a key stream from Keccak-256(x(S) ‖ counter) and XOR it with the message bytes.
  • Decryption. The receiver computes S = dR = drG = rQ, rebuilds the same key stream and XORs again. Only the holder of d can do this.

2Caesar cipher

Key s ∈ {0, …, 25}. Encryption C = (P + s) mod 26, decryption P = (C − s) mod 26; other characters are left unchanged.

4Statistical cryptanalysis of the Caesar cipher

A Caesar cipher only relabels letters, so the histogram of a ciphertext is the histogram of the language rotated by the key. The algorithm:

  1. Train on a corpus: letter frequencies fi and letter-pair (bigram) probabilities.
  2. For every candidate key s from 0 to 25, decrypt the ciphertext.
  3. Score each candidate: χ² = Σ (Oi − Ei)² / Ei with Ei = n·fi (lower is better), or a bigram log-likelihood (higher is better), or the number of common English words found (exhaustive search + dictionary).
  4. Return the best-scoring key.

Effectiveness against ciphertext length

Reading the results: with 10–20 letters the observed histogram is too noisy and several shifts look plausible; from about 40–80 letters the true key becomes clear (exact figures change from run to run). The dictionary method needs word boundaries and fails on very short ciphertexts, while bigram scores use more of the language structure than single-letter counts. Limits: the method assumes a known language, a monoalphabetic shift and a representative corpus; ciphertexts without spaces or in a different language lower the success rate, and a polyalphabetic cipher (Vigenère) breaks the one-histogram assumption.

5Attack on the toy ECC scheme

The attacker knows the curve, G, the public key Q from section 1 and the bound d < 2b. The goal is d. Two algorithms are implemented:

  • Exhaustive search: compute G, 2G, 3G, … until jG = Q. At most 2b group operations.
  • Baby-step giant-step (BSGS): write d = i·m + j with m = ⌈√2b⌉. Store the baby steps jG in a table; then walk Q − i·m·G until a table entry matches. About 2√2b operations at the cost of √2b memory.

Why it does not scale to a proper key

6Discussion

Statistical attack vs key-space attack

  • The Caesar attack is ciphertext-only and statistical. It exploits the structure of the plaintext (uneven letter frequencies) that the cipher fails to hide; its success is probabilistic and grows with ciphertext length. With only 26 keys one could also try them all and recognise the right one by eye.
  • The ECC attack is algebraic and combinatorial. It needs no ciphertext and no assumption about the message (it works even on random data): it uses the public Q and the size of the key space, and it succeeds with certainty if enough operations are performed.

Why a proper ECC key resists

With d uniform in about 2256 values, exhaustive search needs ~2255 group operations on average. The best generic attacks (BSGS, Pollard rho) still need ~2128 operations, and BSGS would also need ~2128 stored points, which is physically impossible (table above). Statistics do not help either: the ciphertext bytes are pseudorandom.

Weaknesses: key space vs scheme design

  • From the restricted key space: exhaustive search, BSGS, and Pollard's kangaroo/rho, which finds d in ~√2b steps with almost no memory. The same weakness appears if the ephemeral r is drawn from a small range: R = rG reveals r and then S = rQ decrypts without d.
  • From the design of the toy scheme: no authentication, so flipping a ciphertext bit flips the same plaintext bit (malleability); reusing r reuses the key stream (c₁ ⊕ c₂ = m₁ ⊕ m₂); R is not validated; a weak random generator for r would break it even with a 256-bit d; message length is not hidden. A real design (ECIES, or ECDH + an authenticated cipher such as AES-GCM) fixes these.
