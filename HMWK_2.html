5Historical context

SHA-2 / SHA-512 vs Keccak / SHA-3

SHA-2 uses the Merkle–Damgård construction; Keccak uses the sponge construction and won the NIST SHA-3 competition (final 2012, standard 2015). Ethereum adopted Keccak-256 before standardisation; NIST then changed the padding byte (0x06 in SHA3-256, 0x01 in Keccak), so the outputs differ. Section 2 shows the difference.

6Why several primitives, and what about statistics?

Different jobs. BIP-39/32/44 manage and derive keys from one backup; secp256k1 gives the private/public relation and signatures; Keccak-256 shortens and uniformises the identifier without exposing the public key; EIP-55 catches transcription errors. Separate roles mean each piece can be replaced independently and each task uses the most suitable tool.

Statistical properties. Mnemonic entropy and the private key must be uniform and unpredictable (a weak random generator breaks the wallet). HMAC-SHA512, PBKDF2 and Keccak show avalanche: one flipped input bit changes about half of the output bits (section 2). The point (x, y) is not a hash output, so Keccak-256 is applied before the address. The address digits are close to uniform, so the EIP-55 capitalisation pattern behaves like a pseudorandom label.
